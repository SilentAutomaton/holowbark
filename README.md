# Holowbark

[English](README.en.md)

Android-клиент WireGuard, который соединяется со своим сервером через оверлейную
сеть [Yggdrasil](https://yggdrasil-network.github.io/), а не через открытый
интернет. Права root не нужны.

Смысл в сервере, **у которого нет доступного порта**. Порт WireGuard закрыт
межсетевым экраном от публичного интернета, и единственный вход — адрес сервера
в сети Yggdrasil, то есть адрес, существующий только внутри mesh-сети. На
публичном IP-адресе нечего сканировать, распознавать и блокировать.

Готовые APK-файлы — в разделе [Releases](https://github.com/SilentAutomaton/holowbark/releases).

## Путь пакета

```
  ваше приложение
     │
     ▼
  интерфейс TUN  ──────────────────────────────────────┐
     │                                                 │
     │ адрес назначения в 200::/7?                     │ всё остальное
     ▼                                                 ▼
  оверлей Yggdrasil                            WireGuard / AmneziaWG
     │                                                 │
     │                   зашифрованные кадры WireGuard ┘
     │                                     │
     │  упакованы в IPv6/UDP и ◄───────────┘
     │  отправлены в оверлей
     ▼
  физическая сеть → mesh-сеть → ваш сервер
```

Здесь два туннеля один поверх другого. WireGuard шифрует трафик обычным образом,
но у него нет собственного сокета: его протокольные кадры возвращаются
в приложение, упаковываются в дейтаграмму IPv6 UDP с адресом сервера в оверлее
и передаются через Yggdrasil. Трафик, который и так адресован в оверлей, минует
WireGuard полностью.

При запуске приложение убирает адреса пиров Yggdrasil из маршрутов туннеля,
чтобы транспорт, который несёт туннель, сам не шёл через этот туннель.

## Состояние и ограничения

- **Параметры обфускации AmneziaWG разбираются и передаются дальше, но не
  протестированы.** Проверенный вариант — обычные конфигурации WireGuard.
- Android 8.0 (API 26) и новее. До API 33 исключения пиров задаются разделением
  маршрутов: это дольше настраивается, но работает так же.
- Туннель доступен ровно настолько, насколько доступен оверлей. Без подключённых
  пиров Yggdrasil соединения не будет. Разумное начальное количество — десять
  пиров и больше.
- Если в настройках выбраны приложения, каждое новое соединение проверяется:
  чьё оно. Иначе исключённое приложение могло бы привязать сокет прямо
  к `tun0` и пройти через туннель. Пока выбраны приложения, ping и traceroute
  через туннель не работают, а фрагментированные UDP-пакеты теряются. Проверка
  работает с Android 10 (API 29); на более старых версиях её нет.
  Приложение, которое само привязывает сокет к `tun0` (например, торрент-клиент
  с настройкой «только через VPN»), при этом теряет TCP-соединения: Android
  не сообщает их владельца. Отключите в нём такую привязку: трафик и так идёт
  через туннель.

## Быстрый старт

1. Нажмите **Add server** и импортируйте файл `.conf` от WireGuard. Если сервера
   ещё нет, настройте его по инструкции ниже.
2. При первом запуске приложение уже выбрало публичные пиры страны, в которой
   находится телефон (по мобильной сети, затем по SIM-карте, затем по региону в
   настройках системы): те, что публичный список считает рабочими. Если список не
   удалось обновить, берутся все пиры страны из сохранённой копии: последней
   загруженной, а если её ещё нет — из списка, встроенного в приложение. Чтобы
   изменить выбор, откройте **Settings → Peers** и либо выберите пиры из
   публичного списка — кнопки **Add all** и **Remove all** берут всю страну
   сразу, — либо впишите собственный пир: свой узел Yggdrasil или узел
   в локальной сети.
3. Вернитесь назад и нажмите **Connect**.

**Settings → Peers → Find peers automatically** заменяет пиры страны поиском.
При каждом подключении, до создания туннеля, приложение пробует публичные пиры,
которые у него уже есть (сохранённый список или встроенный в приложение, так что
скачивать ничего не нужно), начиная со страны, где находится телефон, и запускает
туннель с первыми тремя ответившими пирами с разных хостов. Когда туннель поднят,
поиск продолжается в фоне вне туннеля и подключает каждый ответивший пир, до 20,
один проход на подключение. В следующий раз найденные пиры идут первыми. Если две
минуты не отвечает ни один пир и этому нет объяснения (у телефона есть сеть, экран
включён, не работают ни Battery Saver, ни Doze), приложение ищет заново с нуля:
подключает ответивших и отбрасывает прежних, которые не ответили, не перезапуская
туннель. Смена сети даёт прежним пирам свежие две минуты. После повтора, который
никого не поднял, пауза до следующего удваивается, до 30 минут. Пробуются только пиры, открывающие обычное TCP-соединение (`tcp`, `tls`, `ws`,
`wss`); `quic`-пиры пропускаются. Пиры, которые вы вписали или отметили сами,
остаются в обоих режимах. Выключение поиска возвращает пиры вашей страны, как при
первом запуске.

Публичный список показывает пиры такими, какими их видит его сборщик из своей
сети. Кнопка рядом с **Add all** проверяет все пиры страны с самого телефона, и
после этого **Add all** берёт те, что ответили отсюда. Проверка работает только
при отключённом туннеле: при включённом она шла бы через него.

Раздел **Settings → Server** хранит все импортированные файлы `.conf` под их
именами. Там же выбирается другой сервер; он заработает при следующем
подключении. Любой сервер можно переименовать, а удалить — любой, на котором
сейчас не работает туннель.

Кольцо вокруг кнопки — это и есть туннель. Каждый сегмент внешнего кольца —
один подключённый пир Yggdrasil, поэтому видно, как оверлей
собирается. Внутреннее кольцо — туннель WireGuard поверх него; он поднимается
после того, как сервер ответит на проверочный пакет через mesh-сеть. Если туннель
остановился, а оверлей работает, кнопка **Restart tunnel** перезапускает только
туннель, не разрывая оверлей.

## Настройка сервера вручную

Сервер WireGuard, доступный только через оверлей. Его порт UDP закрыт от
публичного интернета, и единственная точка входа — его адрес в сети Yggdrasil.

### 1. Yggdrasil

Пакеты для всех платформ находятся на странице
[yggdrasil-network.github.io/installation](https://yggdrasil-network.github.io/installation.html).
Для Debian и Ubuntu:

```bash
curl -o /etc/apt/trusted.gpg.d/yggdrasil.gpg \
  https://neilalexander.s3.eu-west-2.amazonaws.com/deb/key.gpg
echo "deb https://neilalexander.s3.eu-west-2.amazonaws.com/deb/ debian yggdrasil" \
  > /etc/apt/sources.list.d/yggdrasil.list
apt update && apt install yggdrasil
yggdrasil -genconf > /etc/yggdrasil/yggdrasil.conf
systemctl enable --now yggdrasil
```

Добавьте несколько публичных пиров в массив `Peers` в файле
`/etc/yggdrasil/yggdrasil.conf` — список находится на сайте
[publicpeers.neilalexander.dev](https://publicpeers.neilalexander.dev/).
Затем узнайте адрес сервера в оверлее:

```bash
yggdrasilctl getSelf | grep '"address"'
# "address": "200:xxxx:xxxx:xxxx:xxxx:xxxx:xxxx:xxxx"
```

### 2. WireGuard

```bash
apt install wireguard-tools
echo "net.ipv4.ip_forward=1"          >> /etc/sysctl.d/99-forward.conf
echo "net.ipv6.conf.all.forwarding=1" >> /etc/sysctl.d/99-forward.conf
sysctl -p /etc/sysctl.d/99-forward.conf
```

### 3. Ключи

```bash
SERVER_PRIV=$(wg genkey); SERVER_PUB=$(echo "$SERVER_PRIV" | wg pubkey)
CLIENT_PRIV=$(wg genkey); CLIENT_PUB=$(echo "$CLIENT_PRIV" | wg pubkey)
echo "Публичный ключ сервера: $SERVER_PUB"
echo "Публичный ключ клиента: $CLIENT_PUB"
```

### 4. Конфигурация сервера

Определите внешний интерфейс командой `ip route | awk '/^default/{print $5}'`,
затем создайте файл `/etc/wireguard/wg0.conf`:

```ini
[Interface]
Address    = 10.100.0.1/24
ListenPort = 51820
PrivateKey = <SERVER_PRIV>
MTU        = 1420

# Преобразование адресов; замените eth0 на свой внешний интерфейс
PostUp  = iptables -t nat -A POSTROUTING -s 10.100.0.0/24 -o eth0 -j MASQUERADE
PreDown = iptables -t nat -D POSTROUTING -s 10.100.0.0/24 -o eth0 -j MASQUERADE

# Закрыть порт от интернета: IPv4 полностью, IPv6 кроме адресов из Yggdrasil
PostUp  = iptables  -I INPUT -p udp --dport 51820 -j DROP; \
          ip6tables -I INPUT -p udp --dport 51820 ! -s 200::/7 -j DROP
PreDown = iptables  -D INPUT -p udp --dport 51820 -j DROP; \
          ip6tables -D INPUT -p udp --dport 51820 ! -s 200::/7 -j DROP

[Peer]
PublicKey  = <CLIENT_PUB>
AllowedIPs = 10.100.0.2/32
```

```bash
systemctl enable --now wg-quick@wg0
```

### 5. Конфигурация клиента для Holowbark

```ini
[Interface]
PrivateKey = <CLIENT_PRIV>
Address    = 10.100.0.2/24
DNS        = 1.1.1.1
MTU        = 1420

[Peer]
PublicKey           = <SERVER_PUB>
Endpoint            = [200:xxxx:xxxx:xxxx:xxxx:xxxx:xxxx:xxxx]:51820
AllowedIPs          = 0.0.0.0/0, ::/0
PersistentKeepalive = 25
```

В поле `Endpoint` должен быть адрес сервера в сети Yggdrasil из шага 1: по нему
приложение понимает, что туннель нужно вести через оверлей. Импортируйте файл
в разделе **Settings → Server**.

Значение `MTU` лучше задать явно на обоих концах, а не полагаться на автоматическое
определение. Программа `wg-quick` вычисляет незаданный MTU из маршрута до конечной
точки пира, и если эта точка — адрес `200::`, маршрут проходит через
интерфейс Yggdrasil, у которого MTU равен 65535. Поэтому настольный клиент
`wg-quick` без явного указания поднимется примерно с MTU 65455. Сам Holowbark по
умолчанию использует 1420 и учитывает значение из файла `.conf`.

## Настройка сервера через wg-easy (Docker)

[wg-easy](https://github.com/wg-easy/wg-easy) — это веб-интерфейс для управления
WireGuard. Следуйте его
[руководству по установке](https://wg-easy.github.io/wg-easy/latest/getting-started/).
Единственное отличие для Holowbark — переменная `WG_HOST`: в ней нужно указать
адрес сервера в сети Yggdrasil, а не публичный IP-адрес.

```
WG_HOST=[200:xxxx:xxxx:xxxx:xxxx:xxxx:xxxx:xxxx]
```

После этого в каждой клиентской конфигурации, созданной через интерфейс, будет
правильный `Endpoint`. Скачайте файл `.conf` и импортируйте его
в разделе **Settings → Server**.

Когда настройка завершена, закройте оба порта от публичного интернета:

```bash
# WireGuard: IPv4 полностью, IPv6 кроме адресов из Yggdrasil
iptables  -I INPUT -p udp --dport 51820 -j DROP
ip6tables -I INPUT -p udp --dport 51820 ! -s 200::/7 -j DROP

# Веб-интерфейс: точно так же
iptables  -I INPUT -p tcp --dport 51821 -j DROP
ip6tables -I INPUT -p tcp --dport 51821 ! -s 200::/7 -j DROP

apt install iptables-persistent -y && netfilter-persistent save
```

После этого веб-интерфейс остаётся доступным изнутри оверлея по адресу
`http://[200:xxxx:...]:51821` или через туннель SSH:

```bash
ssh -L 51821:localhost:51821 user@<сервер>
# затем откройте http://localhost:51821
```

## Сборка

| Инструмент | Версия |
|---|---|
| Go | 1.21 или новее |
| gomobile | последняя, устанавливается командой `go install golang.org/x/mobile/cmd/gomobile@latest` |
| Android SDK | platform-35, build-tools-35 |
| Android NDK | r27 (`ndk;27.2.12479018`) |
| Java | 17 или новее |

```bash
make setup    # первый запуск: компоненты SDK, gomobile, исходники Go
make all      # holowbark.aar и отладочный APK
make install  # установка на подключённое устройство через adb
```

Остальные цели:

```bash
make deps         # забрать исходники Go на фиксированных ревизиях и пропатчить
make aar          # только holowbark.aar
make apk          # отладочный APK (нужен собранный aar)
make apk-release  # неподписанный релизный APK
make rebuild      # clean-aar и полная пересборка
make deps-reset   # заново забрать исходники Go
```

Если файл `app/libs/holowbark.aar` уже собран, можно работать напрямую через
Gradle:

```bash
./gradlew assembleDebug
./gradlew test              # модульные тесты, устройство не нужно
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

### Библиотека на языке Go

Файл `holowbark.aar` объединяет Yggdrasil и AmneziaWG в одном архиве: два
отдельных архива несли бы каждый свою копию среды выполнения gomobile `go.Seq`
и конфликтовали бы. Его размер около 49 МБ, и он **не хранится в репозитории** —
соберите его один раз командой `make aar`.

Исходники на языке Go тоже не хранятся. Команда `make deps` забирает их в каталог
`.deps/` на тех ревизиях, которые зафиксированы в `Makefile` (`YGG_REF`,
`ANET_REF`), и накладывает патчи из `deps/patches/`:

| Патч | Что меняет |
|---|---|
| `yggdrasil-go/0001-…` | открывает биндингам `SendToKey`, `KeyForAddress` и `ProbeNode`, чтобы туннель обращался к серверу по ключу, а не ждал поиска ключа по адресу |
| `yggdrasil-go/0002-…` | фиксирует зависимости, нужные `contrib/awgmobile` и gomobile |
| `yggdrasil-go/0003-…` | QUIC-линк передаёт в TLS имя сервера: имя хоста пира или значение `sni=`; раньше `sni=` у `quic://` игнорировался |
| `yggdrasil-go/0004-…` | каждый исходящий сокет к пиру (`tcp`, `tls`, `ws`, `wss`, `socks`, `quic`) перед соединением проходит через обратный вызов хоста, так что линк, открытый при поднятом туннеле, можно держать вне него |
| `yggdrasil-go/0005-…` | привязки получают `AddPeer` и `RemovePeer`, чтобы менять пиры работающего узла, и `SetProtector`, сторону хоста для обратного вызова выше |
| `anet/0001-…` | убирает `//go:linkname` на приватные кеши зон IPv6 из стандартной библиотеки |

Каждый патч начинается с объяснения, зачем он нужен. Единственная строка,
зависящая от машины, — `replace` на пропатченный anet — пишется командой
`make deps`, в патче её нет.

Точка входа для gomobile — файл `contrib/awgmobile/awgmobile.go`, и другого
своего кода на Go в репозитории нет; `make deps` копирует его
в дерево исходников, потому что компилироваться он должен внутри того модуля.

Каталог `.deps/` — результат сборки. Прежде чем наложить патчи, `make deps`
возвращает отслеживаемые файлы к зафиксированной ревизии, поэтому правка, сделанная
там, пропадёт при следующей сборке — ей место в патче. Чтобы добавить новый:
поправьте дерево, снимите изменения командой
`git -C .deps/yggdrasil-go diff -- <файлы> > deps/patches/yggdrasil-go/0004-….patch`, и
следующий `make aar` их подхватит. `make deps-reset` удаляет деревья и забирает
их заново.

## Устройство приложения

```
app/src/main/kotlin/net/holowbark/
├── vpn/      туннель: служба, оба менеджера, маршрутизатор, кодек пакетов,
│            прокси DNS, разбор адресов пиров, сторож восстановления
├── peers/    список публичных пиров — загрузка, кэш, разбор
├── config/   разбор файлов .conf от WireGuard и AmneziaWG
└── ui/       экраны Compose, навигация, модель представления, кольцо подключения
```

Вся граница между Kotlin и Go — это два файла. `YggdrasilManager` оборачивает
`mobile.Yggdrasil`, а `AwgManager` оборачивает `awgmobile.Backend`; больше ни один
файл не обращается к нативным классам, поэтому остальной код можно тестировать
без устройства.

Два туннеля соединяет файл `contrib/awgmobile/awgmobile.go`.
Он подставляет AmneziaWG вместо настоящего интерфейса TUN и настоящего сокета их
аналоги на каналах, поэтому и открытый трафик WireGuard, и его зашифрованные
кадры попадают в Kotlin, а не в ядро. Дальше приложение свободно направляет эти
кадры через оверлей.

Маршрутизация на интерфейсе TUN:

| Адрес назначения | Путь |
|---|---|
| `200::/7` (оверлей) | напрямую в Yggdrasil |
| `198.18.0.53:53` | разделяющий прокси DNS, если включён DNS оверлея |
| всё остальное | туннель WireGuard |

Правила оформления кода описаны в файле [CODESTYLE.md](CODESTYLE.md).

## Устранение неполадок

Во всех этих случаях сначала откройте **Settings → Logs**. Там последние 500
строк журнала, и их можно скопировать в буфер обмена.

**Yggdrasil не выходит из состояния «Connecting».** Ни один пир не отвечает.
Добавьте больше пиров на экране Peers и предпочитайте географически близкие.
Публичные пиры регулярно выходят из строя, поэтому список, работавший месяц
назад, может быть полностью нерабочим.

**Yggdrasil подключён, но слой туннеля остаётся в состоянии «Reaching server…».**
Оверлей работает, а ваш сервер в нём не отвечает. Проверьте на сервере
`systemctl status yggdrasil`, убедитесь, что команда `yggdrasilctl getSelf`
выдаёт тот же адрес, который указан в поле `Endpoint`, и что порт WireGuard
открыт для диапазона `200::/7`, а не закрыт для всех.

**Соединение установлено, но ничего не открывается.** Обычно причина в DNS. Если
сервер DNS из конфигурации доступен только через туннель, он может не отвечать —
попробуйте `1.1.1.1`. Если включён DNS оверлея, отключите его в настройках,
чтобы сузить круг причин.

**Имена в зоне `.ygg` не разрешаются.** Включите DNS сети Yggdrasil в
настройках. По умолчанию он выключен, потому что направляет все запросы через
резолверы оверлея.

**Небольшие страницы открываются, а крупные загрузки останавливаются.** Это
несовпадение MTU: одна сторона отправляет пакеты, которые вторая не принимает, и
потери нигде не записываются в журнал. Задайте `MTU = 1420` и на сервере, и в
клиентском файле `.conf`. В строке журнала при подключении видно, с каким значением
MTU приложение работает на самом деле.

**Работало, но перестало после того, как экран долго был выключен.** Отключите
для Holowbark оптимизацию расхода батареи. Иначе Android приостанавливает процесс,
и соединения с пирами оверлея разрываются по тайм-ауту. Приложение чинит это само:
когда сервер перестаёт отвечать, оно заново подключается к пирам, а если этого мало —
пересобирает оверлей. Проверочные пакеты уходят только пока туннель простаивает,
поэтому на активном туннеле это ничего не стоит.
